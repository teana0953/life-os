## Why

[issue #84](https://github.com/loftapartment/life-os/issues/84)：「[overview] 增加顯示下一次生理期時間」，並且要有捷徑去生理期頁面。

`predictedNextStart` 後端早就算好了（最後一次起始日 + 最近 6 次的平均週期），但**只出現在生理期頁的統計卡裡** —— 要看下一次是什麼時候，得先想到去 記錄 → 生理期。而這正是那種「偶爾想起來才會查、但查的時候通常有點急」的資訊。

**參考 chaodays 的結果：它沒有這個功能。** 抓下 `chaodays.app` 的前端 bundle 逐字看過，生理期功能的全部字串是 `平均週期`／`平均經期`／`生理期記錄`／`生理期起訖日`／`備註`／`顯示過去一年記錄`／`回到本月記錄`，整份 bundle 沒有 `預測`／`預計`／`下次`／`predict`；它的「資訊總覽」頁是今日體重體脂／今日身體代謝／今日飲食記錄／我的成就／焦點資訊／即將到來的預約課程，**沒有任何生理期卡片**。lifeos 在這件事上已經走在前面（預測是我們自己算的），所以呈現方式沒有現成範本可抄，這份提案自己決定。

## What Changes

總覽加一張卡，放在**體重目標與月曆之間**，整張可點，點進生理期頁（`/health/menstrual`，巢狀子路由）。

**位置**：照護仍在最上面 —— 那是唯一有時效、漏了補不回來的資訊。但也不能放最後：月曆卡是一整格月曆加三個達成率環，放它後面等於手機上必定在第一屏外，而這張卡的全部價值就是「不用點進去就看得到」。

卡片分六種狀態：

| 情況 | 顯示 |
| --- | --- |
| 今天落在**任何一段**已記錄的週期內（含尚未結束的） | 進行中・第 N 天（預測**還在未來**時才加「下次預計 8月20日」） |
| 預測日在未來 | 8月20日・還有 12 天 |
| 預測日是今天 | 預計今天 |
| 預測日已過 | 預計 8月20日・已過 3 天還沒有紀錄 |
| 只有一筆紀錄 | 再記錄一次就能預測下次 |
| 一筆都沒有 | 還沒有生理期紀錄 |

**「資料不足」分成兩句**：後端要兩筆才算得出週期，所以 0 筆的人「再記錄一次」仍然不會有預測 —— 而 0 筆正是每個新使用者的起始狀態。

**「進行中」仍然把預測講出來**：很多人只記開始不記結束，那筆一直開著的話這張卡就永遠不顯示 issue 要的那個日期，等於功能對那群人不存在。

**逾期狀態是必要的，不是裝飾**：後端的預測沒有被夾到未來，所以只要有一陣子沒記錄，那個日期就會落在過去。單純把它印出來會變成「下次生理期：7月2日」而今天是 7月28日 —— 讀起來像壞掉。但**措辭講「還沒有紀錄」而不是「已晚」**：這個狀態在結構上分不出「真的晚了」和「忘了記」，而後者更常見，中文的「晚了 N 天」則有明確的醫療聯想。

**「進行中」排在預測前面**：人在經期當下最先想看的不是下一次的日期。第 N 天用那一段的起始日算，不設上限 —— 忘了關的舊紀錄顯示「進行中・第 45 天」是對的，它正好在說「你忘了關」。

判斷要掃過**全部** periods，不能只看 `lastPeriod`（它是起始日最大的那次）：補記一段開始更早、結束更晚的週期時，生理期頁的月曆會把今天標成經期日，而只看 `lastPeriod` 的總覽卡會說「還有 12 天」—— 兩個畫面對同一天講相反的話。

資料不足時卡片**仍然在、仍然可點**：它同時是去生理期頁的捷徑，而沒資料的人正是最需要那個捷徑的人。

## Capabilities

### Modified Capabilities

- `menstrual-ui`: 總覽 SHALL 顯示下一次生理期的預測與距今天數，並 SHALL 作為進入生理期頁的捷徑；預測日已過時 SHALL 說明它已過，而不是印出一個過去的日期。
