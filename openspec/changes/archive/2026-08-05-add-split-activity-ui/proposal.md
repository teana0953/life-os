## Why

後端(backend PR #72,已 merge)在記錄八種分帳異動的事件時間軸,含**刪除**與**修改**——那正是使用者現在完全看不到、卻會改變自己欠多少的事:一筆支出被刪掉後,列與 shares 都消失,使用者只會發現餘額變了。`GET /api/split/activity?limit=&cursor=` 已上線。

## What Changes

分帳分頁多一層分頁:**總覽 / 變更紀錄**。

**現有的「最近活動」清單留著,兩者不是同一種東西**:

| | 現有的「最近活動」 | 新的「變更紀錄」 |
|---|---|---|
| 內容 | 目前**存在**的支出 + 還款 | **發生過**什麼,含已刪除的 |
| 排序 | 使用者填的消費日期 | 記錄時間 |
| 可否編輯 | 每列可點進去編輯 | 不可(目標可能已不存在) |
| 有誰做的 | 無 | 有 actor |

- 事件依時間倒序,keyset cursor 分頁,捲到底載下一頁。
- actor 是自己時主詞顯示「你」。
- **還款的方向要對三種讀者角色都正確**(付款方、收款方、群組第三人)——後端存的 `actor_is_payer` 是相對於 actor 的。

## Impact

- **文案渲染是唯一真正困難的地方**:八種事件 × 你/別人,加上還款方向的六種組合。**寫錯了畫面看起來完全正常、只是方向相反**,而使用者會據此以為別人還了錢。要抽成純函式 + 表格驅動測試 + 逐種突變。
- 分頁要防無限迴圈(`next_cursor` 為 null 後仍請求、或重複同一個 cursor)。
- 新增的 ARB 字串很多,**兩個語系都要補齊**(既有 issue #99:ARB parity 零測試)。
- token 用 `IdTokenProvider`(PR #126 之後的形狀),**不要**複製 inline 的 `await repository.idToken() ?? ''`。
- 不動 `FinanceScaffold` 的底部導覽——那會變成第三層。
