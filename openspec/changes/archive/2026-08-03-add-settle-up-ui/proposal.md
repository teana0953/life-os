## Why

還款與分帳自付額的後端已上(life-os-backend PR #69),前端一條都沒接:使用者看得到「Bob 欠你 450」卻沒辦法結清,財務總覽也看不到自己在分帳上真正花了多少。本 change 補上,財務藍圖收尾。

使用者裁定:**結清的入口在餘額列上**(看到欠多少的同一個地方就能處理,預填全額與幣別);**分帳自付額在總覽獨立一列**,跟記帳支出並列、不加進支出總額。

## What Changes

- `lib/contexts/split/` 延伸:`Settlement`(帶 `fromDisplayName`/`toDisplayName`,名字由後端給)、`SplitSpending`、repository 三個方法、`CannotSettleWithSelf`。
- **結清只從雙人餘額發起,`group_id` 一律 `null`**:群組淨額是「每位成員對整個群組」,沒有 from/to 這一對,套正負規則會把錢記反。群組頁改成同時顯示既有的群組淨額(標籤改成「分帳淨額(不含還款)」,因為它不會因結清而變動)與**我跟每位成員的雙人餘額**,結清從後者發起。
- **結清 sheet**:從餘額列進入,預填該幣別全額;**方向由餘額的正負決定,使用者不能選**——讓使用者選等於把後端那條「兩段 SQL 符號相反」的陷阱搬到 UI 上。一列多幣別就有多個結清入口,一次結一種。
- 允許部分還款與多還;**多還在送出前提醒會讓對方變成欠你,但不阻擋**(後端刻意允許,那是真實情況)。
- 還款可刪(後端沒有 PATCH),**入口只對建立者或付款人顯示**,二次確認且指名對象與金額。
- **還款在清單裡與支出明顯區分**(不同圖示 + 文案寫明「還款」)——後端不用反向支出充數就是為了這個,前端不能在呈現上抵銷掉。
- **財務總覽加「分帳自付額」一列**:獨立請求、**自己的載入狀態與錯誤**(`FinanceController` 目前是單一 status + 一包 `Future.wait`,併進去會讓任一失敗把整頁變錯誤),並沿用既有的**換月競態防線**;**不進支出總額、不進預算進度**(後端預算刻意不算分帳,前端加了就會與超支判定不一致);沒有分帳資料的月份不顯示那一列;**該列載入失敗不得讓整個總覽壞掉**。
- ARB 三檔新增文案;錯誤文案映射在 presentation。

範圍外:債務重組(一鍵最少轉帳)、還款提醒/通知、分帳自付額進趨勢圖。

## Capabilities

### Modified Capabilities

- `split-ui`:結清入口與 sheet、還款清單與刪除。
- `finance-ledger-ui`:總覽新增分帳自付額一列。

## Impact

- 修改 `lib/contexts/split/**`、`lib/contexts/finance/**`(總覽與 repository)、`lib/l10n/app_{en,zh_Hant,zh}.arb`。
- **既有三個財務 tab 的數字不得改變**——分帳自付額是新的一列,不動支出總額,也不動預算卡。
- 後端零改動。
