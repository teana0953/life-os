# 記帳畫面接上分帳鏡像

## Why

後端 PR #79 已經部署:白名單內幣別(TWD 等 10 種)的分帳自付額**現在是真的個人交易**,會進支出總額、預算與警示。前端還停在舊契約,所以**現在的 app 正在說反話**:

- 總覽的分帳自付額卡片寫著「不計入上方的支出總額,也不計入預算」—— 對 TWD 剛好相反。那張卡是使用者判斷「這筆錢算進去了沒」的**唯一依據**,而它現在給的是錯的答案。
- 記帳明細裡多出來的那些交易看起來跟自己記的一模一樣,**按刪除會拿到 400**,改金額也會。
- 後端新的 409(分帳在你讀取到寫入之間被改了)掉進通用分支,顯示 `Finance request failed (status 409).` —— 一句英文加狀態碼。
- 分帳建立表單沒有分類欄位,所以**每一筆鏡像都落在「其他」**,分類預算等於白修。

## What Changes

- **總覽的分帳卡逐幣別分兩組**:已計入支出總額的、與未計入的(不支援的幣別)。不再用一句話蓋全部。
- **鏡像交易的編輯 sheet 改成「事實 + 兩個可編輯欄位」**:金額/日期/幣別/類型當唯讀摘要呈現(不是灰掉的輸入框),分類與備註照常可編輯,刪除鈕**拿掉**並說明要去分帳頁刪。
- **記帳明細列上標記**來自分帳,不要讓人點進去才發現不一樣。
- **409 當成「重新載入」而不是「儲存失敗」**:意思是資料在你打開之後被改了,再試一次會再撞一次。
- **分帳建立/編輯表單加分類選擇**,從付款人自己的財務分類挑(送名字,不是 id)。

## Impact

- `FinanceTransaction` 加 `splitExpenseId`;`SplitExpense` 加 `categoryName`。
- **split 的表單需要 finance 的分類清單** —— 目前 split context 完全沒有這個存取,要接線。
- **`PATCH /api/split/expenses/:id` 是全取代**:編輯時沒重送 `category_name` 會把它清掉,連帶把所有沒被使用者改過的鏡像移回「其他」。
- 新增一個 finance 例外對應 409。

## 明確不做的(受現有資料與路由限制)

- **標題不顯示「跟誰分帳」。** 交易列只帶 `split_expense_id` 與 `note`(分帳的描述),沒有付款人、沒有群組;要顯示得多打一次 API,而 finance context 沒有 split 的 repository。標題用「來自分帳 · <描述>」。
- **「前往分帳」只能到分帳 tab,不能跳到那一筆。** 路由只有 `/finance` 與 `/finance/groups/:id`,沒有單筆分帳的路由,而交易列也不帶 group id。深連結是另一個 change。
