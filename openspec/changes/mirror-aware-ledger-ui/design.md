# Design

## D0:現在的 app 在說反話,這是修 bug 不是加功能

後端 PR #79 **已經部署**(deploy success,2026-08-06)。所以在這個 change 上線之前:

- 總覽的分帳卡對 TWD 使用者說「不計入支出總額,也不計入預算」,而它**兩個都計入了**
- 記帳明細裡有使用者沒記過的交易,按刪除拿到 400
- 409 顯示 `Finance request failed (status 409).`

**排序:卡片的錯字第一。** 它是使用者判斷「這筆錢算進去了沒」的唯一依據,而它現在給的是錯的答案 —— 那會讓人以為自己還有預算可花。

## D1:一句話蓋不住兩種幣別

舊文案是一句話,因為舊行為對所有幣別一致。**現在不一致了**:白名單內(TWD 等 10 種)已經計入,白名單外(泰銖等)沒有,而後端逐幣別回一個 `counted_in_transactions`。

**不能只是把那句話改掉** —— 改成「已計入」對泰銖是假的,改成「未計入」對台幣是假的。**要分兩組,各講各的**,而且句子要放在**它自己那組的金額旁邊**,不是卡片頂端一句話管全部。

只有一組時不要顯示另一組的標題 —— 空標題比沒有更容易被讀成「另一組是零」。

## D2:鎖住的欄位當「事實」呈現,不要當「壞掉的輸入框」

直覺做法是把 disabled 的輸入框留在原位。那是這個選項最常見的做法,也是它會變難用的原因:五個欄位裡三個灰掉,整張表單讀起來像壞了,而使用者要在噪音裡找出哪兩個能動。

**上半是唯讀摘要(純文字),下半只有真的能動的兩個欄位:**

```
來自分帳 · 晚餐                        [前往分帳]
900 TWD · 7月15日
───────────────────────────
分類   [ 餐飲 ▾ ]
備註   [______________]

金額、日期要到分帳頁改;這筆也只能在那裡刪除。
```

使用者看到的是「兩個欄位」而不是「五個欄位其中三個壞了」,而**為什麼**在第一行就講完。

## D3:刪除鈕**拿掉**,不是 disabled

灰掉的刪除鈕仍然邀請人去按,然後什麼都不發生 —— 比 400 好一點,但仍然是死路。換成一句說明,並給一個真的出口。

## D4:標題**不顯示「跟誰」**,「前往分帳」**不跳到那一筆**

這兩個是現有資料與路由的限制,不是偷懶:

- 交易只帶 `split_expense_id` 與 `note`(分帳當時的描述),**沒有付款人、沒有群組**。要顯示「跟 Ben 分帳」得多打一次 API,而 finance context 沒有 split 的 repository。
- 路由只有 `/finance` 與 `/finance/groups/:id`,**沒有單筆分帳的路由**,而交易也不帶 group id。

所以標題是「來自分帳 · <描述>」,而「前往分帳」到分帳 tab。**深連結是另一個 change,不要在這裡半做。**

## D5:409 是「重新載入」,不是「儲存失敗」

409 的意思是「分帳在你打開這張 sheet 之後被改了」。**再試一次會再撞一次** —— 使用者手上那份 `expected` 值已經過期了,而後端比對的就是它。

所以要:告訴使用者記錄變了、把現在的值拿回來、讓他在新的基礎上重做決定。**不要**沿用 `financeSaveFailed`,那句話會把人推向一個保證失敗的動作。

現在 409 掉進 `FinanceFetchFailure('Finance request failed (status $statusCode).')` —— 一句英文加狀態碼給中文使用者。要有自己的例外型別。

## D6:split 的表單需要 finance 的分類,而它現在完全拿不到

`grep -rn "FinanceCategory" lib/contexts/split/` **零筆**。這是這個 change 唯一的接線工作。

分類**送名字不送 id**:分類是 per-user 的,付款人的 id 對其他參與者沒有意義,而每個參與者的鏡像是拿名字去對自己的分類清單。

## D7:`PATCH` 是全取代,沒重送就會被清掉

編輯分帳時若沒把 `category_name` 一起送回去,後端會當成「沒有分類」,而**所有沒被使用者手動改過的鏡像會退回「其他」** —— 一次只改金額的編輯,會靜默改掉別人帳本裡的分類。

表單開啟時要把現有的分類讀進 state,送出時一起送。**這跟 sheet 裡其他欄位的處理一致**(`_currency`、`_day` 都是這樣),照著做即可,但要有測試釘住 —— 這種「少送一個欄位」的錯不會有任何報錯。
